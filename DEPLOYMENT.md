# Deployment status

## Current status

The workspace displays no fabricated participant data. Google Drive statistics, report processing, and workbook writes remain controlled by server-side environment flags and institutional approval. Do not enable real participant workflows before that approval.

## Actions needed before real use

1. **Set up the independent Supabase project.** Apply `supabase/OWN_SUPABASE_SETUP.sql` and configure the local/deployed environment using [OWN_SUPABASE_SETUP.md](./OWN_SUPABASE_SETUP.md). Do not point the account provisioning script at the old project.
2. **Provision the initial accounts.** After the new project settings and Auth email delivery are tested, run `npm run provision:accounts`. The script sends email invitations to the two Super Admins and stores one-time Centre Admin passwords in the ignored local `temp-credentials.csv`. Share those credentials privately; do not commit or email the CSV.
3. **Configure and test email.** Follow [OWN_SUPABASE_SETUP.md](./OWN_SUPABASE_SETUP.md) for the independent Supabase Auth configuration. Retain email confirmation and closed public sign-up. Set the institution-approved sender name, sender address, and reply-to address. If using an institutional sending domain, have its DNS administrator add the exact domain-verification and mail-authentication records shown by the email service, then wait for verification to pass. Review the confirmation, invitation, and password-reset message templates and redirect links. Send and receive all three message types with approved test accounts, including a completed reset. Actual delivery has not yet been tested.
4. **Configure direct read-only Drive access.** In Google Cloud Console, enable the Google Drive API, create a service account, and create a JSON key. Add its `client_email` and `private_key` to the server-only variables in `.env.local` using `.env.example`. Set `MASTER_TRACKER_SHEET_ID` and `MASTER_TRACKER_TAB` to the approved tracker spreadsheet and exact tab. Share only the 16 mapped destination workbooks and that master tracker with the service-account email as Viewer; do not share the parent reports folder containing PDFs. Never commit or send the JSON key.
5. **Verify the 16 centre destinations and tracker mapping.** Confirm the configured master tab contains one row per centre and the expected headers, then verify every existing workbook mapping and its participant-ID header. Test read-only with a non-sensitive copy before any write is enabled; never infer mappings from folder names alone.
6. **Approve data handling.** Obtain institutional approval for hosting and data location, authorized roles, retention/deletion, audit fields, backups, incident response, and validation rules. Confirm that the selected Supabase project and Netlify region are approved destinations for participant health data.
7. **Complete independent review.** Test invitations, email verification, recovery, role assignment, cross-centre denial, audit outcomes, PDF processing and deletion, Excel matching/formula preservation, duplicate prevention, concurrent writes, and all explicit error states using non-sensitive test copies. Confirm server/database controls rather than relying on hidden screens. Do not enable real uploads or writes until each check passes.
8. **Configure Netlify.** Connect the `own-backend` branch, use the included `netlify.toml`, and set the variables in [OWN_SUPABASE_SETUP.md](./OWN_SUPABASE_SETUP.md). Keep private keys and token secrets in Netlify's environment-variable UI, never in the repository.
9. **Expose the extraction service.** Run the local Python service and a Cloudflare Tunnel to `http://127.0.0.1:8765`. Set the public tunnel URL in `VITE_TERIIP_EXTRACTION_SERVICE_URL` in Netlify, and add the exact Netlify site origin to the local service's `TERIIP_EXTRACTION_ALLOWED_ORIGINS`. Keep the service and tunnel online when extraction is needed.
10. **Deploy only after approval.** Publish for centre-wide use only after integration, email delivery, identity roster, access controls, data workflows, tunnel availability, and institutional security/privacy review are verified.

## Available locally

For local development, configure `.env.local`, then use `npm install`, `npm run dev`, and `npm test` (or the matching Bun commands). Drive reads remain disabled until `TERIIP_DRIVE_READS_ENABLED=true`; set it only after the access and privacy/security review is approved. Local development and preview are not otherwise approved for real participant data.
